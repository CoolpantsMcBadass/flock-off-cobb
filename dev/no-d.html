Flyer without the CSS d property

WebKit does not implement the CSS d property, so on an iPhone the flyer cannot morph and falls back to the @supports not (d: path(…)) branch in index.html. This page reproduces that branch in Chrome so it can actually be looked at: it fetches the real page and rewrites two things — every d:path(…) declaration is deleted (the d="…" attributes in the markup stay, which is the whole point of them being there), and the @supports not condition is swapped for one that is always true.

What to check: the burst has its shape at rest; the poster is visible and framed when open; the burst fades rather than stretching into a giant star; and the pop still throws its droplets. What this can't show: anything else WebKit differs on — only a real device does that.

Gotcha: transitions in these iframes don't advance while the tab is throttled, so a hero stuck at opacity:0 or a sheet stuck at its rolled height is this page not being painted, not the fallback failing. Click into the frame, or read a specified value rather than a computed one — a computed value mid-transition is the animated value, which is the start value when the clock never ran. For a reading with no such doubt, generate a real file instead: swap the @supports condition and strip the d:path(…) declarations with a script, write it to the repo root so assets/ still resolves, and open it directly.
