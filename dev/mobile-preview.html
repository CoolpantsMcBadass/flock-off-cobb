DeFlock Cobb — mobile preview

The site in a phone-width frame. Media queries inside an iframe measure the iframe, so this is the real mobile layout, not a scaled screenshot — the flyer picks up its max-width:860px rules and the caption reads "Tap for info". Tap the burst to open it: below 861px the hover path is switched off by design, so the flyer opens on tap and closes on a tap outside. Everything else about the pop is the same.

What this can't show: real touch (these are mouse clicks), the iOS/Android URL bar eating vertical space, and system font rendering.

Getting it onto a real phone is not reliable, so don't plan on it. The obvious route is http://<this Mac's IP>:<the port serving this page> on a phone on the same wi-fi (ipconfig getifaddr en0 for the IP; python3 -m http.server does listen on every interface). It failed on 2026-08-14 with the Mac and the phone on the same network, the firewall off, the server answering that exact URL from the Mac in milliseconds, and Safari still timing out with "the server stopped responding" — which is what client isolation on the access point looks like, and plenty of routers ship with it on. If that happens, a phone Personal Hotspot with the Mac joined to it puts both ends on a network that isn't isolated.

For the engine rather than the hardware, drive real WebKit instead: npx playwright install webkit, then playwright-core with devices['iPhone 13']. That is what has actually caught the WebKit bugs in this project, and it takes real tap() events.
